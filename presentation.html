DFD

Dumpster Fire Diving

Automated pipeline failure analysis for Red Hat Trusted Libraries
with multi-agent AI, self-evolving taxonomy, and interactive chatbot

4 pipeline types monitored 3 specialized AI agents 14 chatbot tools auto-evolving taxonomy

The Problem

  • Calunga (Red Hat Trusted Libraries) pipelines fail across build, integration test, EC, and release
  • Root cause analysis is manual and time-consuming
  • Failures come from many sources: infra, flakes, builds, releases...
  • No historical view — same issues keep recurring unnoticed
  • No way to search across failures or find patterns
  • Classification categories drift — no systematic taxonomy management

The Solution

An OpenShift-native system that
fetches failed pipelines from KubeArchive,
runs multi-agent AI analysis,
builds a self-evolving taxonomy,
and serves a React dashboard with AI chatbot.

Build Integration Test Enterprise Contract Release

All 4 Calunga pipeline types — from Fromager wheel builds to Pulp publishing

Collection Pipeline

1. Collect Query KubeArchive per pipeline type (48h window) → download logs, TaskRun JSON, metadata
Key artifacts to DB, full archives to S3. Skips already-known runs.
↓
2. Analyze Multi-agent pipeline per failure (asyncio, 5 concurrent)
Manager triage → Specialists (parallel) → Manager Synthesis
↓
3. Evolve Consolidate proposals → consolidate novel root causes → update taxonomy
Novel patterns auto-promoted to taxonomy after 3+ occurrences in 90 days
↓
4. Re-analyze Queue unknowns for re-analysis with updated taxonomy
Full history preserved — analysis_version increments, all versions viewable

Multi-Agent Analysis

Each failure is analyzed by a team of specialized AI agents:

1. Manager / Triage — reads metadata + logs, forms hypothesis, selects 0–2 specialists via tool call
2. Log Analyst — deep log analysis: compilation errors, Fromager output, pip/setuptools failures, timeout/OOM patterns, import errors
2. Historical Analyst — cross-analysis comparison, validates against past data, detects over-broad categories, identifies trends
3. Manager / Synthesis — reads full investigation board, resolves conflicts, produces final classification + optional rule proposal

Simple failures: 2 API calls — Complex failures: 4 API calls
All agents use extended thinking (10k tokens) for reasoning chains
Agents communicate via shared investigation board in DB

Self-Evolving Taxonomy

Propose Synthesis agent proposes new rules when it discovers novel patterns
Claude-assisted semantic deduplication — groups similar proposals into canonical labels
↓
Novel Tracking Classifications not matching any rule are flagged as novel (taxonomy_matched = false)
Shown as purple labels with * prefix in the dashboard
↓
Auto-Consolidation Claude groups semantically similar novel root causes across 90-day window
Groups with 3+ distinct pipeline runs → auto-promoted to taxonomy rules
↓
Re-analyze New rules trigger re-analysis of unknowns & affected failures
Full history preserved — all analysis versions viewable in dashboard

AI Chatbot

Interactive Claude-powered assistant in the dashboard:

Capabilities

  • Investigate specific failures ("Why did run X fail?")
  • Cross-failure pattern analysis ("What's trending?")
  • Read raw logs and artifacts on demand
  • Browse S3 archives for deep investigation
  • View full multi-agent conversation logs
  • Manage taxonomy: accept/reject proposals, merge/edit/delete rules

Implementation

  • Claude Sonnet 4.6 via Vertex AI
  • 14 tools (query, read, search, taxonomy CRUD...)
  • Tool-use loop (max 15 iterations)
  • SSE streaming with keepalive
  • Session persistence in PostgreSQL
  • Per-conversation cost tracking
